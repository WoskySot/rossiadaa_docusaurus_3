**边码**是汉译书籍版心外侧那一列数字，表示**原文的页码**：读到某处，白边里的数字告诉你"从这里往下，是原书第几页的内容"。本站的做法是——白边由容器留出，页码由你写，落点由浏览器实测。

这一页也开着边码（front matter 里的 `bianma:`），下面示例里的页码是真实的。为了版面清爽，本页关掉了页码之间的连线（`rule: false`），连线效果看 [样例页](/docs/completed/bianma-demo)。

## 一、效果示例

^^37^^这一页开着边码，白边里的 37、38、39 就是下面三段里三个标记画出来的。

页码贴在你写标记的那一行。这句话说到一半插一个标记，^^38^^它就对在这一行上；折行位置变了，它也跟着挪。

^^39^^标记写在段首时，对齐的是这一段的第一行，不会跑到上一段的末尾去。

本页关掉了页码之间的连线（`rule: false`），连线效果看 [样例页](/docs/completed/bianma-demo)。

## 二、语法

在译文对应原文分页的位置插入：

`^^37^^`

标记本身**零宽、不可见、不占位**，你写的文本只会出现在白边里。规则：

- 必须成对出现；落单的 `` ^^ `` 原样保留为文字，不会报错也不会吞字。
- 内容是纯文本，不超过 64 字符，不能换行、不能含 `` ^ ``。不要指望在里面写加粗或链接——那里只该放页码这类短标记。
- 想在正文里显示这串符号本身，放进行内代码或代码块即可（本节与上文示例都是这么写的）。

## 三、启用：两种方式

| 场景 | 怎么写 | 生效范围 |
| --- | --- | --- |
| 整页 | front matter 写 `bianma: true` | 该页全部版心内容 |
| 整页，改参数 | front matter 写 `bianma: {side: right, gutter: 72}` | 同上 |
| 局部 | 正文里用 `<Bianma>…</Bianma>` 包住 | 被包住的那部分 |

第三种不需要 `import`——组件已注册进全局 MDX 作用域（`src/theme/MDXComponents.js`）。但**标签名必须大写** `Bianma`，小写会被 MDX 当成原生 HTML 元素。它不限于 docs：`src/pages/*.mdx` 里同样能用。

⚠️ **开关与页码是两件事**：`bianma:` 只负责给这一页留出白边，白边里画什么由 `^^…^^` 决定。开了白边却一个标记都没写，得到的是一条空白边——所以别在不需要的页面开它。

最小例子：

````mdx
---
title: 某篇译文
bianma: true
---

^^37^^译文照常写，在原文第 37 页开始的地方插一个标记。
^^38^^第 38 页开始的地方再插一个。
````

## 四、参数（三个）

front matter 的 `bianma:` 与组件 props 是同一套（front matter 写 YAML，组件写 JSX 属性）：

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `side` | `'left'` | 白边在正文哪一侧：`'left'` / `'right'` |
| `gutter` | `56` | 白边宽度（px）。页码两三位够用；写 `p. 142` 这类长文本再调大 |
| `rule` | `true` | 是否在相邻页码之间拉细线（表示"这段行文属于哪一页"） |

````mdx
整页改成白边在右侧、宽 72px、不要连线：

```yaml
bianma:
  side: right
  gutter: 72
  rule: false
```

或者只包一段：

<Bianma side="right" rule={false} gutter={72}>
  这一段的白边在右侧，且没有连线。
</Bianma>
````

嵌套没问题：外层管外层的内容，内层量内层的内容，互不干扰（[样例页](/docs/completed/bianma-demo) 里演示了）。

## 五、显示逻辑

- **落点**：页码贴在**你写下标记的那一行**。写在段落中间，就对齐那一行；写在段落开头（前面是别的块），就对齐该段第一行。你不需要知道它会折成第几行。
- **排序**：先按实测位置自上而下排，落在同一行时再按正文里的先后。所以即使标记写在行内元素内部，顺序也不会错乱。
- **连线**：从本页页码画到下一个页码出现为止，表示这中间的行文属于本页；最后一个一直画到版心底部。
- **撞行**：两个标记离得太近、页码落到同一行时（例如原书那一页很短，在译文里不足一行），后一个会自动下移让开，小勾改成虚线提示它不在本行上。
- **重排**：窗口缩放、侧边栏折叠、中文字体加载完成、图片撑高版面、明暗主题切换，都会重新测量后再画。

## 六、桌面 / 移动 / 暗色 / 打印

| 场景 | 表现 |
| --- | --- |
| 桌面 >996px | 白边按 `gutter`（默认 56px），页码 0.75rem |
| 移动 ≤996px | 白边收窄到最多 44px，页码 0.7rem，功能保留 |
| 亮色 | 页码取 `emphasis-700`（白底 5.7:1，过 WCAG AA） |
| 暗色 | 页码取 `emphasis-400`（暗底 5.6:1） |
| 打印 | 白边恢复完整宽度，颜色改成不依赖主题的灰 |

## 七、适用范围

- **适合**：译文正文、影印文件说明、任何"要能说清对应原文哪里"的长文本。
- **不适合**：列表页、索引页、以代码或图为主的页面——那些页面没有原文页码可对，白边只白占宽度。
- **不受内容类型限制**：段落、标题、引用块、表格、列表里都能放标记；代码块内部不会被解析。
- **一页可以有多组**：`<Bianma>` 可嵌套，各自量各自的内容。

## 八、注意事项

:::warning[页码是稳定的，位置不是]
`^^42^^` 里的数字由你给定，**不随折行变化**，所以"原文第 42 页"可以当稳定引用（页面重排只是让它上下挪动）。

但反过来不成立：**别引用"译文第几行"**——网页上一行折成几行取决于视口宽度与字号，换个屏幕就不成立了。要指向别处，用标题锚点或脚注。
:::

- **锚点在正文里不可见、不占位**：零宽元素，不参与折行；复制正文时也不会把页码带走。
- **首屏白边一定是空的**：落点必须由浏览器实测，静态 HTML 里量不出来。所以服务端渲染与首次客户端渲染都是空白边，测量在挂载之后进行；白边由 CSS 无条件预留，数字"迟到"**不会**引起布局跳动。
- **关掉 JavaScript 就没有页码**：白边还在，页码整列消失。它是辅助信息，这样降级可以接受。
- **万一组件样式丢失**：锚点会退回成正文里的普通小字（刻意的降级，比彻底丢掉对应关系好），把样式补回来即可恢复。

## 九、写给维护者

- **语法插件**：`plugins/bianma-mark/index.js`（构建期 rehype 插件，在 `docusaurus.config.js` 的 `docs.rehypePlugins` 注册）。它只做一件事：把 `^^文本^^` 变成零宽锚点 ``<span class="bianmaAnchor" data-bianma-mark="文本">``。跳过 `pre`/`code`，否则讲解语法的页面会把示例自己吃掉。
- **组件**：`src/components/Bianma/`（`index.js` + `styles.module.css`）；整页开关在 `src/theme/DocItem/Content/index.js`；全局注册在 `src/theme/MDXComponents.js`。
- **测量逻辑三句话**：锚点自身零宽、量不到行盒，所以借它旁边**第一个真实字符**用 `Range.getClientRects()` 取行矩形；多个锚点先按实测位置排序，再处理撞行；渲染只写进白边、不碰正文容器——所以观察正文的 `MutationObserver` 不会被我们自己画数字反复触发。
- **样式**：集中在 `styles.module.css`，配色走 Infima 变量，明暗自动适配。窄屏只能用 `min(var(--bianma-gutter), …)` 在使用点收窄——`--bianma-gutter` 是内联下发的，媒体查询改写不了它。
