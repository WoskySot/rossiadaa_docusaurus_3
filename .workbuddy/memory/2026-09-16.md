# 2026-09-16

## 定位：@easyops-cn/docusaurus-search-local 装上了却"不能用"

用户报告安装本地搜索插件后遇到严重问题、插件无法工作。没有报错日志，靠**实际复现**定位，共三条根因。

### ① 构建直接挂掉（响亮）—— `keywords: text` 语法错
- `docs/completed/01-about.mdx:4` 写了 `keywords: text`。
- `keywords` 是 **Docusaurus 原生 front matter 字段**，schema 是
  `JoiFrontMatter.array().items(JoiFrontMatter.string().required())`（见
  `node_modules/@docusaurus/plugin-content-docs/lib/frontMatter.js:22`）→ **必须是字符串数组**。
- 后果：`ValidationError: "keywords" must be an array` → `[ERROR] Loading of version failed` →
  整个 build 中止 → 没有产物、没有索引 → 插件看起来"完全不工作"。
- 修复：改成 YAML 数组。**注意这跟搜索插件无关**，是纯 Docusaurus 内容校验。

### ② 中文搜不到（静默）—— 插件选项 `language` 没开
- `docusaurus.config.js` 的插件选项里 `language` 是注释状态 → 默认 `"en"`。
- README 原文：`language` 默认 `"en"`，"For Docs using Chinese, it is recomended to set:
  `language: ["en", "zh"]`"。
- **反证实验**（同一份内容，只差这一个选项，用无头 Chrome 真敲键盘）：

  | 关键词 | 无 `language` | 有 `language: ["en","zh"]` |
  | --- | --- | --- |
  | 编译局 | 没有找到任何文档 | 命中 |
  | 边码 | 没有找到任何文档 | 命中 |
  | 脚注 | 命中 | 命中（条目更多） |
  | docusaurus | 命中 | 命中 |

- 底层是 `@node-rs/jieba`（插件依赖）做分词；实测 `cut('弹出窗口式脚注的写法说明', true)`
  → `弹/出/窗口/式/脚注/的/写法/说明`，模块本身正常。
- 修复：`language: ["en", "zh"]`。

### ③ "在 dev 里怎么搜都没结果"—— 索引只在 build 时生成（设计如此）
- 插件把索引用 **`postBuild`** 钩子生成：`dist/server/server/index.js:25`
  `postBuild: postBuildFactory(config, searchIndexFilename)`。
  `docusaurus start` 不会跑 `postBuild`，所以 dev 下**根本没有 `/search-index.json`**。
- dev 下任何查询都显示插件自带文案
  「⚠️ The search index is only available when you run docusaurus build!」
  （见 `dist/client/client/theme/SearchBar/EmptyTemplate.js`：只有 `NODE_ENV==='production'`
  才显示正常的"没有找到任何文档"）。
- ⚠️ **排查时踩到的假线索**：dev server 对不存在的 `/search-index.json` 会走 SPA 兜底，
  返回 **HTTP 200 + `text/html`**（1872B 的页面外壳）。**只看状态码会误判成"索引存在"**，
  必须看 `content-type`。
- 结论：**验证搜索只能用 `yarn build` + `yarn serve`**，在 `yarn start` 里验证是假阴性。

### ④ 潜在隐患（不是本次病因，但迟早出事）—— 双锁文件
- 今天用 **yarn** 装的包：`yarn.lock`（23:04:49，含 easyops）+ `node_modules/.yarn-integrity`
  （说明 node_modules 现在归 yarn 管）。
- 但 `package-lock.json` 是 09-09 的，**不含 easyops**（`packages['']` 的 dependencies 里没有）。
- 后果：`npm ci` 会因 package.json 与 lock 不同步直接报错；`npm install` 会重写
  package-lock 并可能替换掉 yarn 装的树 → 插件时有时无。
- 建议二选一：留 yarn（删 `package-lock.json`），或改用 npm（`npm install` 后删 `yarn.lock`）。

### 排查过但确认没问题的

- `docsRouteBasePath`/`blogRouteBasePath`/`docsDir`/`blogDir` 都是默认值，与本站一致 ✓

- **在 rspack 下能用**：本项目 `future.v4: true` + `@docusaurus/faster 3.10.2`（dev 日志

### 顺带确认的一个能力

`keywordsDocuments`）。所以"用 front matter keywords 提升搜索命中"的思路是对的，
只要写成数组。

## 续：IDE 报 TS2322（`themes` 里的搜索插件配置）

用户反馈"仍然在报错"，报错**不在运行时、而在编辑器的 TypeScript 检查**里
（`owner: typescript`、`code 2322`、`severity 8`）。docusaurus.config.js 第 1 行有 `// @ts-check`，
所以 VS Code 的 TS 语言服务会检查这个 JS 文件。

### 现象（两条，同时出现）
```
docusaurus.config.js(171,7): TS2322: 不能将类型"string"分配给类型"PluginModule<unknown> | DeepPartial<PluginOptions>"
docusaurus.config.js(173,8): TS2322: 不能将类型"PluginOptions"分配给类型"PluginModule<unknown> | DeepPartial<PluginOptions>"
  类型"PluginOptions"中缺少类型"string"的索引签名
```

### 根因（逐层读完 .d.ts 得到，不是猜的）
```ts
// @docusaurus/types/src/plugin.d.ts
export type PluginOptions = {id?: string} & {[key: string]: unknown};
export type PluginConfig<Content = unknown> =
  | string | [string, PluginOptions] | [PluginModule<Content>, PluginOptions] | PluginModule<Content> | false | null;
// @docusaurus/types/src/config.d.ts
themes: PluginConfig[];
export type Config = Overwrite<DeepPartial<DocusaurusConfig>, {...}>;   // ← 关键
```
用户配置对象要赋给 `Config`，于是 `themes` 变成 `DeepPartial<PluginConfig>[]`，
元组槽位变成 **`DeepPartial<PluginOptions>`**——它要求一个**字符串索引签名**。

而插件 README 让你写的是
`/** @type {import("@easyops-cn/docusaurus-search-local").PluginOptions} */`，
它指向插件的 **interface**。**TypeScript 里 interface 不会获得隐式索引签名**（type alias /
对象字面量会），所以赋给那个槽位必然失败。第 171 行那条 `string` 报错是**连带**的：
元组整体不匹配时 TS 会把两个位置都标出来，把选项那个修好，171 行也会一起消失。

### 修法（实测 6 种才定的）
在受管工作区装了一份 TypeScript（项目里没有），用
`tsc --noEmit --allowJs --checkJs --moduleResolution bundler` 跑对照：

| 变体 | 结果 |
| --- | --- |
| README 原样 | 2 条错误 |
| 去掉选项上的 JSDoc | 0（但丢插件选项类型提示） |
| 换成 Docusaurus 自己的 `PluginOptions` | 0（也丢插件类型） |
| **插件类型 `& Record<string, unknown>`** | **0，且保留类型提示 ← 采用** |
| 用包名字符串代替 `require.resolve` | 0（说明与 `require.resolve` 无关） |
| 给整个元组加 JSDoc | 仍 2 条（关键在**选项对象的类型**，不是元组形状） |

最终写法：
```js
/** @type {import("@easyops-cn/docusaurus-search-local").PluginOptions & Record<string, unknown>} */
({ hashed: true, language: ["en", "zh"] }),
```

### 验证
① 带/不带 `--skipLibCheck`，`docusaurus.config.js` 均 **0 条诊断**；
② 类型提示仍在：故意写 `hashed: 123` 会被拦下（TS2352）；
③ `docusaurus build` 退出码 0、`search-index.json` 正常产出。

### 附带发现
- 项目**没有 `tsconfig.json` / `jsconfig.json`**，VS Code 用的是默认编译选项。不带 `--skipLibCheck`
  时依赖声明文件里共有 15 条历史噪音（`@docsearch/react`、`@types/mdx`、`react-helmet-async`、
  `@docusaurus/module-type-aliases`，以及插件自带的 `dist/types/index.d.ts` 1 条）。
  **加一个最小 `jsconfig.json`（`skipLibCheck: true`）可以清掉这些噪音**——已作为可选建议告知用户，
  没有擅自添加（会改动他的工具链配置）。
- 这台机器上原本没有 TypeScript，也没有 VS Code 自带的副本；装法：
  `mkdir <受管工作区> && npm install typescript@5.4.5`（项目外的 `~/.workbuddy/binaries/node/workspace`，
  不污染项目）。这是一条通用技巧：**要复现 IDE 的 TS 报错，得自己搞一份 tsc**。
