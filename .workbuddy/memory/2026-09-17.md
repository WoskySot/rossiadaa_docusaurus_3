## 非移动端也套用同一套脚注弹窗定位（弹窗自动定位对齐触屏）

### 需求
触屏早有"上方优先 → 放不下翻面 → 贴边平移 → 溢出内部滚动"的实测定位，指针设备没有。
要求两边行为一致，且不改变指针设备原有的显示与交互。

### 为什么必须删掉 `≤996px` 那条分支
它的 `transform` 是纯 `translateY(...)`，**不含 `--fn-pop-shift`** → 在窄窗口里会绕开平移量，
贴边平移直接失效（新机制反而更糟）。而且它是"只属于桌面"的第二套几何，与"两边一致"的目标冲突。
贴边问题现在统一由平移量解决，窄窗口（实测 480px）同样不出视口。

### 关键实现细节
- **量尺寸前必须保证不是 `display:none`**：隐藏时 `getBoundingClientRect()` 全 0。
  触屏路径先挂 `[data-fn-open]` 所以本来就是可量的；指针路径的显示由**伪类**决定，
  而"伪类何时生效"与"事件处理器何时执行"的先后不适合依赖 →
  `fitPopover()` 里统一兜底：量之前若仍是 `display:none`，临时 `display:block` 量完还原
  （此时 `visibility:hidden`，不会闪）。
- 用 `pointerover`/`pointerout` 而不是 `pointerenter`/`pointerleave`：后者**不冒泡**，
  没法用 document 委托；前者配合 `relatedTarget` 判断"真的进出容器"，而鼠标移到弹窗自身上时
  `relatedTarget` 仍在容器内 → 不当作离开（与 CSS 的 `:hover` 覆盖子节点一致）。
- 离开时**必须复位**（含两个 CSS 变量）：留着上次的 `--fn-pop-max`，下次打开会先被旧上限截一次，
  量到的"自然高度"就是错的。已有断言覆盖（E3）。

### 验证：24 项全通过（桌面 1280×800 / 480×700 / 360×256 + 触屏 390×844 回归）
- A 门控：环境确为指针设备；未悬停不显示。
- B **上方优先 / 翻面**：编号5（上方余量 417px）→ 不翻面；编号2（上方余量 **−7px**）→ `flip=below`；
  编号7（贴近页底）→ 不翻面。三条都"不重叠编号"且竖直不出视口。
- C **贴边平移**：480px 宽下 10 个编号**全部**在视口内，其中 9 个触发了平移。
- D **限高 + 内部滚动**：
  - D1 反向断言——正常视口（480×700，自然高 98px）**不**开内部滚动（没有误判）；
  - D2 自适应矮视口（360×256）：`max-height=93px`（= 该侧真实余量）、`overflow-y:auto`、
    弹窗 top 154.5 / bottom 247.5 仍在 256 高的视口内；
  - D3 内部滚动时 `::after display:none`。
- E **原交互回归**：悬停显示 ✓；指针设备不挂 `data-fn-open` ✓；鼠标移到弹窗自身上保持显示 ✓；
  移开后状态完全复位 ✓；**未悬停直接单击仍是一次即跳转**（偏差 0.48px + 高亮）✓；Tab 聚焦仍显示且已定位 ✓。
- F **触屏回归**：第一下弹窗不跳转 ✓；定位算法仍生效 ✓；第二下跳转（偏差 0.2px + 高亮 + 弹窗收起）✓。
- G 控制台 0 异常。
- H **小三角跟随**：480px 宽下 10/10，平移/居中后三角尖端与编号中心的偏差都在容差内。

### 两个测量坑（都是我自己的测试写错，不是实现问题）
1. **小三角位置不能凭感觉算**：`::after` 的 `left` 百分比相对于**内边距盒**（要加 1px 边框），
   而 `transform: translateX(-50%)` 的百分比相对于**边框盒**；另外旋转围绕自身中心，
   `-50%` 已经把中心移到 `left` 处，所以尖端 x = `popLeft + borderLeft + left`（**不是** `+left+5`）。
   算式写错时会看到"所有编号恒定偏 4px"这种假故障。
2. **测"溢出内部滚动"要先看内容到底多高**：本站最长的弹窗只有 98px，固定用 420px 高的视口时
   两侧都放得下，本来就不该滚动 —— 那次 FAIL 是测试参数选的，不是实现。改成**先量高度、
   再据 vh ≈ 2H+60 选视口**，并补一条"正常视口不该误判"的反向断言。

### 静态产物没变
构建产物里 0 处 `data-fn-*`、0 处 `--fn-*` 内联样式（`data-fn-open` 那 1 处是页面正文里的说明文字），
弹窗仍是纯静态 HTML：新增的一切都发生在浏览器运行时。
