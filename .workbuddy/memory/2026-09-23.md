## aky.moe/watched 实现分析与「用 Docusaurus 复刻」可行性评估（只读调研）

用户给了一个第三方页面 <https://aky.moe/watched/>，要求分析其前端实现并对照官方文档评估用 Docusaurus
复刻的可行性，只出报告、不动代码。产出：`review/aky-watched-复刻可行性评估.md`（340 行）
+ 两张参考截图 `review/aky-watched-桌面.png`（1280×900）、`review/aky-watched-移动.png`（390×844）。

### 最重要的发现
- **该页本身就是 Docusaurus v3.8.1 产物**（`<meta name=generator>`、`<body class="plugin-pages">`），
  源码路径可从主包分块表直接读出：`src/pages/watched/index.tsx`；React **19.1.0**；Vercel 托管。
  所以"能不能复刻"没有悬念，真正成本在数据整理 + 三块自研代码。
- 数据：**一份 TOML 当字符串内联在路由分块里**（分块 1.0MB / br 637KB），运行时解析。
  结构含 `[status]`/`[type]` 两张**文案表**（中文显示名写在数据文件里）+ 7 张数据表；
  条目字段 `name/status/url/cover/names/note/日期`；`name = "-"` 是**分组分隔符**（15 处）。
  封面三级兜底：本地 `./<类>/<名>.{webp,jpg,png}`（`require.context`）→ 同名 `.url` 文本 → `console.warn` 留空。
  `bgm://12345` 简写运行时展开。状态可省略，由"存在同名日期字段"反推。
- 搜索**自研**：Fuse.js `keys:[title 2, names 1.5, _py 1, _romaji 1, _initials 0.6]`、
  `threshold:.4`、`ignoreLocation:true`、`minMatchCharLength:1`；派生字段用拼音库（全拼 + `pattern:'first'` 首字母）
  与假名罗马音库。实测：玉子→1、yuzi→30、yzsc→9、tamako→6、**错字「摇曳百和」→1**。
  搜索态**顶掉标签页**，改按分类分组（「番剧 19」「漫画 1」+ 计数 + × 清除 + 空状态文案），且跨分类。
- 布局：`display:grid; grid-template-columns:repeat(auto-fill, var(--card-width))`，`--card-width`=320px，
  **无任何媒体查询控列数**（实测 1440→4 列、1280/1100→3、997~800→2、600/390→1，卡片恒 320px 不收缩）。
  卡片 320×107（`aspect-ratio:3`）、左侧 103×103 方封面（`object-fit:cover`+黑底）、
  右上状态标签蓝 `#3b82f6`（`border-radius:0 0 0 12px`）、右下备注标签、悬停边框 `#25c2a0`。
- 页面用官方 `<Tabs lazy>`（首屏 HTML 只有 1 个 `tabpanel`，其余分类点开才渲染）。
- 工具类是**手写的 Tailwind 风格子集**（`.flex/.p-4/.text-sm/.ml-2/...`），整份 CSS `--tw-` 出现 0 次。
- 导航栏搜索是该站自己的 `@easyops-cn/docusaurus-search-local`（`search-index.json` 8.6MB），
  **不覆盖这 497 条结构化记录** —— 这是"官方/社区搜索方案替代不了自研搜索"的直接证据。

### 方法备忘（可复用）
- 只用公开产物 + 无头 Chrome 只读探测，未复制对方源码/数据再发布。
  分块文件名要从 `runtime~main.js` 里 `i.u=e=>"assets/js/"+({id:"hash"})[e]+".js"` 解析出来，
  **实际路径是 `<id>.<hash>.js`**（直接猜 `<hash>.js` 会 404 并被 Vercel 的 SPA 兜底返回 200 + text/html，
  这一点和本项目 docs 的教训同源：**不能只看状态码，要看 content-type**）。
- 探测脚本写在临时目录（`probe*.cjs`/`count.cjs`/`dig*.cjs`），跑完已清理；用的是 `headless-ui-verify`
  技能的 `cdp.cjs`（真实鼠标事件 + `performance.getEntriesByType('resource')` 找运行时分块）。
- 搜索框这类受控输入要在页面里用**原生 value setter + dispatch input** 驱动，
  直接改 `.value` React 不认。

## 顺手固化成技能：`web-stack-forensics`（用户级）
- 位置 `~/.workbuddy/skills/web-stack-forensics/`，含 `scripts/forensics.cjs`（14KB，已过 `--check` 与 quick_validate）。
- 五个子命令：`inventory`（指纹/资源/体积/CSS Module 类名频次）、`chunks`（解析 runtime 哈希表并**实测确认**文件名形状）、
  `source`（主包里找源码路径 → 分块 id → 候选 URL）、`pull`（下载，自动验证不是 HTML）、
  `grep`（特征串 + 内置库指纹表：fuse/pinyin/wanakana/lunr/algolia/TOML/…）。
- 写这套时踩到的坑（已写进 SKILL.md）：
  ① 分块文件名**不能硬推**——产物里嵌着 2~3 张 id→hash 表，本站真实形状是 `<hashA>.<hashB>.js`，
  只能"列候选 + 请求验证"；② **别只看 HTTP 状态码**，SPA 兜底把 404 变成 200 + text/html；
  ③ 抓 `<script src>` 不能写 `/<script[^>]+src=/`，内联脚本里的 `=>` 会把标签切歪（要把引号内的 `>` 排除）；
  ④ 判"是不是真 Tailwind"要看产物里有没有 `--tw-` 变量。
