# 项目长期记忆 — 帝俄行政部（Docusaurus 博客）

## 技术栈
- Docusaurus 3.10.2 + React 19，preset-classic，i18n 默认 `zh-Hans`。
- 全局样式入口：`src/css/custom.css`（`theme.customCss` 指定）；组件私有样式放 `styles.module.css`。
- 构建（Windows，managed node）：`node node_modules/@docusaurus/core/bin/docusaurus.mjs build`。

## docs 结构与导航栏
- 文档分 `docs/in-progress/`（施工中）与 `docs/completed/`（已完成）；目录名用英文保 URL 干净，中文只作展示标签。
- 导航栏无「编译局」，改为两个 `docSidebar` 入口 `🛠施工中🛠`／`📕已完成📕`，各指向 `sidebars.js` 的
  `inProgressSidebar`／`completedSidebar`（两个独立侧边栏，各只装自己那个分类）。改栏位名要同时改 config 与 sidebars 的 label。
- 新增文档丢进对应目录即可，侧边栏与 `/docs/` 总览自动同步。
- `docs/overview.mdx` 用 `slug: /` 充当 `/docs/` 落地页（双栏总览，首页按钮指向它）；组件在 `src/components/DocsOverview/`
  （`useAllDocsData()` + 子组件内 `useDocById(id)`）。该页不在任何侧边栏。
- 文件名前缀 `NN-` 会被剥掉（不进 slug/id）并决定排序。
- 脚手架文档（`intro.mdx`、`tutorial-basics/`、`tutorial-extras/`）保留文件与路由，但**不在任何侧边栏**（靠 sidebars.js 显式列举）。
- 移动端（≤996px）：汉堡菜单先显示**当前板块侧边栏**，需点「← 回到主菜单」才见两个栏位入口（Docusaurus 原生行为）。

## 隐藏页面（无导航/侧边栏入口，仅直链可达）
- 三条件叠加：①文件不在任何 `autogenerated` 目录内（放 `docs/` 根目录或自建子目录）；②无 sidebar 列举；③navbar 无入口。
- 该页 `sidebar` 为 `null` ⇒ `{sidebar && ...}` 跳过，**连侧边栏容器都不渲染**，正文满宽。
- 现有：`/docs/`（`overview.mdx`，入口=首页按钮）、`/docs/hidden-pages`（入口=总览页内链）；`intro`、`tutorial-*` 同理。
- `unlisted: true` 才加 `noindex`、不进 sitemap、页顶显示「未列出页」横幅；本项目未使用，隐藏页仍进 sitemap。
- `displayed_sidebar: <name>` 让页面显示某侧边栏但不被其收录。

## 边码（Bianma）—— 译文对应原文页码
- **语义**：白边里的数字是**原文页码**（"从这里往下是原书第几页"），由作者给定；不是自动行号
  （曾做成"每 N 行编号"，2026-09-15 按用户要求改掉）。页码稳定，变的是它在页面上的落点。
- 作者写行内语法 `^^42^^` → `plugins/bianma-mark/index.js`（构建期 rehype 插件，注册在 `config.docs.rehypePlugins`）
  转成零宽锚点 `<span class="bianmaAnchor" data-bianma-mark="42">`（属性 + 隐藏文本子节点双份，样式丢失时可降级可见）。
- 组件 `src/components/Bianma/`；接线 `src/theme/MDXComponents.js`（全局注册 `<Bianma>`，免 import）+
  `src/theme/DocItem/Content/index.js`（读 front matter）。
- 启用：front matter `bianma: true`／`{side, gutter, rule}`，或正文 `<Bianma …>` 包局部。
  默认 `side:'left', gutter:56, rule:true`。**开关只负责留白边**，白边里画什么由锚点决定；
  没写 `bianma` 的页面 DOM 与从前完全一致（不会多出一层 div）。
- **落点规则**：页码贴在作者写标记的那一行——锚点前若还有其所属段落的文字，取前一个字符那行；否则取后一个字符那行。
  判"本段"要往上找最近的**非行内** display 祖先再 `contains()`，直接 `anchor.parentElement.contains()` 会因锚点在 `<a>` 里而失灵。
- 硬规则：**walker 必须排除锚点自身**（`closest('[data-bianma-mark]')`）——锚点内的隐藏文本会让 `nextNode()`
  先返回它自己，零宽矩形把落点退化成"整段矩形"（偏差可达 46px）；行盒只能浏览器实测（`Range.getClientRects()`），
  SSR 渲染空白边，`MutationObserver` 只观察内容容器；窄屏 `min(var(--bianma-gutter), 44px)`；同线撞位后一个下推 2px
  并带 `data-bianma-pushed`；配色 页码 亮 `emphasis-700`(5.7:1)/暗 `-400`(5.6:1)、细线两套都用 `-300`。
- 验证：独立复算"前字/后字"行盒中心 + 移除锚点前后折行不变；样例页/说明页/嵌套/移动/明暗全部偏差 0.00px。

## 弹出窗口式脚注（EPUB 风格）
- 弹窗（纯 CSS）：`plugins/footnote-popover/index.js`（构建期 rehype 插件，挂 `config.docs.rehypePlugins`）把文末定义
  **复制**到每个引用旁 → `<span class="fnRef"><sup><a…></sup><span class="fnPop">…</span></span>`，显隐由
  `.fnRef:hover/:focus-within` 控制且只在 `(hover:hover) and (pointer:fine)` 下启用。副本里块级标签一律改写成
  `<span>+类名`（`fnPopP/fnPopUl/…`），否则 HTML 解析器在 `<p>` 内自动闭合、注解被甩出弹窗——**构建不报错**；
  新增未覆盖的块级标签会出 `HTML minifier diagnostic`，去补 `BLOCK_CLASS`。
- 🚨 **`.fnPop` 的样式必须分两层：基础层 `display:none`（不设媒体查询）+ 指针层 `display:block`。**
  2026-09-15 修掉的严重缺陷：原先把 `position/visibility/opacity/display` 全写进 `@media (hover:hover) and (pointer:fine)`，
  手机匹配不到该查询 → 整条规则不生效 → `.fnPop` 退回 `<span>` 天性（`position:static`/`display:inline`/可见）
  → **插件复制来的注解原文以普通行内文本铺进正文**（首段高度 161.7px → 108.9px，整页 10 处全中）。
  桌面端把窗口缩到 390px 也看不出来——`hover`/`pointer` 媒体特性绑定**输入设备**，与视口宽度无关，
  只有 `mobile:true` + 触摸模拟或真机才暴露。用 `display:none` 而非 `visibility:hidden`（彻底离流，
  且不撑大可滚动区域）。**泛化：凡是"兜底/降级"用的属性都必须写在媒体查询之外。**
- **脚注跳转的居中落点**（唯一一处客户端 JS，**两个方向共用一套算法**）：
  `src/clientModules/footnoteScrollCenter.js`（document 委托监听；旧名 `footnoteReturnScroll.js` 已废）
  + `src/theme/Root.js`（swizzle 的官方 Root 兜底组件，只 `useEffect` 装监听、不产出 DOM）。
  方向由 **`href` 指向的 id 形状**判定：`fn-` = 文末条目（正文→注解）、`fnref-` = 正文编号（注解→正文）；
  `data-footnote-ref` / `data-footnote-backref` 只作旁证。流程 `preventDefault` → 补焦点 → 自己算 `scrollTop` →
  挂 1.6s `.fnRefFlash` 高亮 → `scrollend` 后校正一次。
- ⚠️ **不要用 `scrollIntoView({block:'center'})` 做居中**：它把元素自身的 `scroll-margin` 算进"对齐区域"，
  而 Docusaurus 通过 `MDXComponents/A` 的 `useAnchorTargetClassName` 给**所有带 `id` 的元素**加了
  `anchorTargetStickyNavbar_*`（`scroll-margin-top: calc(3.75rem + .5rem)`）——正文引用 `<a>` 和文末 `<li>` 都有，
  居中会整体偏下约 34px。正解：自己算（`rect.top - 视口顶 + scrollTop` → 减去 `(视口高-元素高)/2`），
  再夹进 `[0, scrollHeight-clientHeight]`，最后夹进"完整可见"区间（上不过吸顶导航栏、下留 24px）；
  元素比可用高度还高时退回"开头对齐到导航栏下方"。导航栏只在确实 `fixed/sticky` 且贴顶时才算遮挡。
- 找滚动容器：从内往外找最近的 `overflow-y: auto|scroll|overlay` 且 `scrollHeight > clientHeight` 的祖先，
  否则 `document.scrollingElement`；**不认 `overflow: hidden`**（弹窗靠它裁剪，认了坐标系就错）；
  遇到 html/body 立刻停（`overflow-x:hidden` 会让 computed `overflow-y` 变 `auto`，body 会被误判）。
  视口高用 `clientHeight`（它才是 `scrollHeight` 的参照系）；绝不改元素自身的 `scroll-margin`（会波及别处的滚动）。
- 焦点：`preventDefault` 后原生"Tab 起点"不会自动挪，要 `focus({preventScroll:true})` 补；
  但**只给非天生可聚焦的元素补 `tabindex="-1"`**（否则会把正文那个 `<a href>` 踢出 Tab 顺序）。
  导航栏高度实时量并只在贴顶时计入，避免 hideOnScroll / 页头把落点带偏。
- ⚠️ 别想用 `scroll-margin-top: calc(50dvh - .5em)` 代替 JS：`scroll-margin` 改的是元素自身几何，
  之后 Tab 聚焦、片段导航、任何 `scrollIntoView` 都会带上它，等于顺手改坏别处的滚动。
- ⚠️ 别用 history API 同步 hash：实测（3.10.2）仅 `pushState` 改 hash 路由层不会跟着滚，但仍刻意不碰——
  `ClientLifecyclesDispatcher.scrollAfterNavigation` 对 hash 变化做的正是**顶格对齐**，将来一接上就会覆盖居中。
- 居中不可能成立时取"最优解"（脚本判据 `clamped && clearsNavbar && fullyVisible`）：目标在文档首屏更上方时
  只能夹在 `scrollTop = 0`（首段引用会偏两百多像素），这是几何限制、不是 bug——要真居中只能给正文加 padding。
- 跳回正文后弹窗会因 `focus-within` 自动出现（脚本聚焦了那个 `<a>`），与原生片段导航一致，刻意保留。
- **触屏 = 两段式点击**（2026-09-15 二轮加）：`src/clientModules/footnoteTouchPopover.js`（与居中模块一起在 `Root.js` 安装）。
  第 1 下弹出该编号的弹窗（不跳转、不改 hash），弹窗已显示时第 2 下才执行跳转；门控 `(hover:hover) and (pointer:fine)`
  命中就**整个模块不安装**（桌面一行代码都不走）。状态放 `data-fn-open` / `data-fn-flip`（翻到下方）/ `data-fn-scroll`（限高内部滚动），
  几何量走 `--fn-pop-shift`（贴边平移）/ `--fn-pop-max`（限高）。落位优先级：上方 → 下方 → 水平平移 → 限高内部滚动；
  **任何情况都不出视口、也不盖住编号**（盖住编号第二下就点不到它了）。
- 触屏监听必须挂**捕获阶段**：先吃掉第一下，冒泡阶段的跳转模块看到 `defaultPrevented` 就会让路；
  顺序反了会"弹窗开了又立刻跳走"。`detail===0`（键盘 / 辅助技术合成点击）**不走两段式**，直接放行跳转。
- 🚨 触屏热区只能做在 `<a>` 自己的 `padding` 上（`padding:.5rem .35rem` + 等量负 `margin`）。
  曾用绝对定位伪元素 `.fnRef::before{inset:-.5rem -.3rem}` 扩热区，伪元素盖在 `<a>` 之上 →
  第二下的 `event.target.closest('a[href]')` 拿到 null → **弹窗关掉了却不跳转**。
  另在跳转模块加 `resolveAnchor()` 兜住"命中落到外层 `.fnRef`"的情况（容器内第一个 `#` 链接即引用本身）。
- 样式底座的分工：`.fnPop{display:none}` 写在媒体查询**之外**；触屏显隐靠 `.fnRef[data-fn-open] > .fnPop`，
  指针设备靠 `:hover/:focus-within`——所以桌面 Tab 聚焦照旧弹窗（没有被基础层的 `display:none` 关掉）。
- **弹窗落位两个平台共用一套算法**（2026-09-17）：`src/clientModules/footnotePopoverFit.js`
  （上方优先 → 翻到下方 → 贴边平移 → 限高内部滚动；只写 `--fn-pop-max`/`--fn-pop-shift` 与
  `data-fn-flip`/`data-fn-scroll`，几何留在 CSS）。调用方按输入设备分工、门控互为反面：
  触屏 `footnoteTouchPopover.js`（点开式）、指针 `footnotePopoverHover.js`（悬停/聚焦式，**不改可见性**）。
  ⚠️ 量尺寸前要保证元素不是 `display:none`（否则 rect 全 0）：触屏先挂 `[data-fn-open]` 所以可量，
  指针路径依赖伪类，故 `fitPopover()` 统一兜底——仍隐藏就临时 `display:block`、量完还原。
  ⚠️ `[data-fn-scroll]` 的 CSS 选择器**不要加 `[data-fn-open]` 前缀**：那是触屏专属状态，加了指针设备就不滚动。
  ⚠️ 别再引入桌面专属的第二套几何：原 `@media (max-width:996px)` 的"窄窗口向左展开"已删——
  它的 `transform` 不含 `--fn-pop-shift`，会绕开平移量。
- 交互细节与实测数据见 `review/mobile-footnote/审查说明.md`（第二轮章节）与
  `.workbuddy/memory/2026-09-17.md`（桌面端定位那一轮的 24 项验证）。

## 本地搜索（@easyops-cn/docusaurus-search-local 0.55.3，2026-09-16 接入）
- 接在 `docusaurus.config.js` **顶层** `themes: [[require.resolve("@easyops-cn/docusaurus-search-local"), {...}]]`
  （不是 `themeConfig`）。`docsRouteBasePath`/`blogRouteBasePath`/`docsDir`/`blogDir` 默认值
  （`/docs`、`/blog`、`docs`、`blog`）与本站一致，无需写。没配 `algolia`，不冲突。
- 🚨 **`language: ["en", "zh"]` 必开**（默认只有 `"en"`）。中文正文不开这一项时**构建照样成功**，
  但中文关键词一律「没有找到任何文档」——静默失效。实测「编译局」「边码」无该选项时 0 结果、加上即命中。
  分词靠插件的依赖 `@node-rs/jieba`（原生模块，装坏会表现成同样的静默失效）。
- 🚨 **索引只在 `docusaurus build` 时生成**：插件挂在 `postBuild`（`dist/server/server/index.js`
  的 `postBuild: postBuildFactory(...)`）。`docusaurus start` 下没有索引，任何查询都显示插件自带文案
  「⚠️ The search index is only available when you run docusaurus build!」——**这不算故障**。
  **验证搜索必须用 `yarn build` + `yarn serve`，在 dev 里验证是假阴性。**
  ⚠️ dev server 对不存在的 `/search-index.json` 走 SPA 兜底，返回 **HTTP 200 + `text/html`**，
  只看状态码会误判成"索引存在"，要看 `content-type`。
- 用 front matter 提升某页权重（插件把渲染出的 `<meta name="keywords">` 单独做成一条高权重索引条目）：
  ```yaml
  keywords:
    - 编译局
    - 归档
  ```
  ⚠️ **必须是数组**。写成 `keywords: text` 会触发 front-matter 校验失败（`ValidationError:
  "keywords" must be an array`），**整个构建挂掉**。`keywords` 是 Docusaurus 原生字段
  （schema 见 `plugin-content-docs/lib/frontMatter.js`），与插件无关。
- 可选：按「施工中/已完成」拆检索域用 `searchContextByPaths`；`hashed: true` 已开。
- ⚠️ **插件选项的 JSDoc 末尾必须带 `& Record<string, unknown>`**，否则 `@ts-check` 报 TS2322：
  ```js
  /** @type {import("@easyops-cn/docusaurus-search-local").PluginOptions & Record<string, unknown>} */
  ```
  原因链：`Config = Overwrite<DeepPartial<DocusaurusConfig>, …>` ⇒ `themes` 是 `DeepPartial<PluginConfig>[]`
  ⇒ 元组槽位是 `DeepPartial<PluginOptions>`（`PluginOptions = {id?: string} & {[key: string]: unknown}`），
  **要求字符串索引签名**；而插件 README 给的那个 `@type` 指向 **interface**，
  **TS 里 interface 没有隐式索引签名** ⇒ 赋值失败。
  报错会同时落在**解析那一行和选项对象那一行**（两条），修好选项后两条一起消失。
  交叉 `Record<string, unknown>` 既满足索引签名，又保留插件选项的类型提示（实测 `hashed: 123` 仍会被拦）。
  另：项目**没有 `tsconfig.json`/`jsconfig.json`**，VS Code 用默认选项；如需清掉依赖声明文件里的
  15 条历史噪音，加个最小 `jsconfig.json`（`skipLibCheck: true`）即可（未擅自添加）。
- 这台机器原本没有 TypeScript；复现 IDE 的 TS 报错要先装一份：
  `npm install typescript@5.4.5` 到 `~/.workbuddy/binaries/node/workspace`（项目外，不污染依赖），
  再跑 `tsc --noEmit --allowJs --checkJs --target es2022 --module esnext --moduleResolution bundler <file>`。

## 约定与注意事项
- 改样式优先覆盖 Infima 的 `--ifm-*` 变量，不硬编码内部类；提优先级用稳定主题类名（如 `theme-layout-footer`）。
- 暗色覆盖一律 `[data-theme='dark']` 作用域；断点统一 **996px**。
- `src/theme/` 已有两处 **wrap（非 eject）** swizzle。wrap 到 `DocItem/Content` 外层时，`.markdown` 仍是原组件的子元素，
  Infima 的直接子代选择器（`.markdown > h2`、`.markdown > *:last-child`）不受影响。
- `onBrokenLinks: 'throw'`：新增 `to`/`href` 前必须确认目标存在。
- 陷阱：Infima `--ifm-footer-link-hover-color` 默认 = `--ifm-color-primary`；页脚背景用主色时必须显式改写悬停色。
- 陷阱：MDX 带标题提示框必须写 `:::tip[标题]`；写成 `:::tip 标题` 会原样输出且**构建不报错**。
- 陷阱：MDX 里写 `{`（JSX/对象字面量）必须包在反引号或代码块内。
- 陷阱：MDX 里**裸写 `<span …>` 之类标签会被当 JSX 解析**——文字消失、标签变成真元素（曾因此凭空多出一个空锚点）。
  文档里要展示标签，必须包反引号。
- 校验自命中坑：全文搜类名会被正文命中。要搜**带 `<` 的标签写法**（`<` 转义为 `&lt;`，双引号不转义）。
- **校验产物别用 CSS Module 的类名**：产物里是 `.rule_T_Uk`、`.mark_DHNO` 这类哈希名，`/\.rule\{/` 永不命中；
  改判 minified 子串（如 `--bianma-rule-color);inline-size:1px;position:absolute`）。
- 🚨 **在 dev server 运行期间给 `docs/` 里的文件改名（或增删），会报
  `× Cannot find module '@site/docs/completed/01-about.md' for matched aliased key '@site'`。**
  成因：`@docusaurus/plugin-content-docs/lib/routes.js:45,51` 把路由模块写成 `modules: {content: doc.source}`，
  而 `doc.source` 就是 `@site/docs/…` 这份别名路径的**原文**（元数据文件名是 `docuHash(doc.source)`，两者一一对应）。
  运行中的 dev server 不会（及时）重建这份路由表，于是它仍旧 `import()` 改名前的路径 ⇒ 打包器解析失败。
  本项目装了 `@docusaurus/faster`（dev 日志里是 `client (Rspack 1.7.12) compiled`），
  所以措辞是 rspack 的 "for matched aliased key" 而非 webpack 的 "Can't resolve"。
  **两个方向都会复现**（改成 `.md` 时报 `.mdx`，改回 `.mdx` 时报 `.md`）——报错里的扩展名只是**残留的那一份**，
  与 `.md`/`.mdx` 谁对谁错无关。`docusaurus build` 每次都重扫 `docs/`，不受影响（三种状态实测全过）。
  **做法：改文件名前先停 dev server，改完再 `npm start`。** 重启后仍报就 `npm run clear`
  （rspack 的持久化缓存在 Windows 上偶发存不下来，日志会打 `persistent cache save failed … 拒绝访问 (os error 5)`）。
  另：`.docusaurus/docusaurus-plugin-content-docs/default/` 会留下旧名字的元数据 JSON（两个并存），
  不直接致病，但也是改名痕迹，`clear` 会一并清掉。
- 产物 HTML 被压缩成**无引号属性**（`href=/docs/`、`class=foo_hash`、`data-theme=dark`），写正则要允许无引号形式。
- 亮色下 html/body **都没有显式背景**（白来自画布默认值）：算对比度时探针 walk-up 找不到不透明背景，要兜底 `#ffffff`。
- 验收：build 时 SSR 所有页面，组件报错会让 build 失败；直接读产物 `**/index.html`，不必开浏览器。
- hast 属性名 `dataBianmaMark` 与 `data-bianma-mark` 都能序列化成 `data-bianma-mark`（property-information 会把 camelCase
  的 data* 属性转成短横线形式）。

## 环境与工具（本机特有）
- 浏览器验收：无 agent-browser／playwright，但有 `C:/Program Files/Google/Chrome/Application/chrome.exe`。
  用 `--headless=new --remote-debugging-port=9222` + Node 22 内置 `WebSocket`/`fetch` 直连 CDP
  （`Emulation.setDeviceMetricsOverride` 改视口、`Runtime.evaluate` 交互、`Page.captureScreenshot` 出图），零安装。
  桌面 1440×900，移动 390×844。⚠️ 若先改视口再截图，**必须等 ≥1.5s 确认重绘**（曾拍到未重绘的旧画面，误判暗色失效）。
- 真实交互验收：用 `Input.dispatchMouseEvent`（mouseMoved/Pressed/Released，press 带 `buttons:1`）发**可信点击**，
  别用 `el.click()`；点击前先 `scrollIntoView({block:'center'})` 把目标摆到视口中间——吸顶导航栏会抢走视口顶部
  0–60px 的点击（曾静默点到导航栏上，表现为"补丁没生效"）；并用 `elementFromPoint` 断言命中目标，否则直接报错。
- `Page.captureScreenshot` 的 `clip` 用**文档坐标**（要自己加 `window.scrollX/Y`），用视口坐标会截出全白图。
- ⚠️ **`Page.captureScreenshot` 的 `captureBeyondViewport` 默认 `true`，会截整页而不是视口**——
  本轮因此误判"移动端没居中"（截图里目标落在图像 2/3 处，与探针 -0.16px 矛盾）。**要截视口必须显式传 `false`**。
- 截图与 DOM 几何冲突时**先信 `getBoundingClientRect()`**；再用**页内注入 `position:fixed` 标线**交叉验证
  （`top:50vh` 一条 + 元素中心一条 + `top:0`/`bottom:0` 两条定边框）：标线是渲染的一部分，
  比按缩放比例目测像素可靠得多。
- bash 缺 `dirname`/`head`/`tail`/`which`，PowerShell 工具**完全无输出** → 一律用 `node -e` 或临时 `.cjs`（用完删）。
- **构建守卫坑**：`build` 收尾删 `build/__server` 会触发 safe-delete 批量守卫（threshold 50/轮）而报错，SSR 其实已跑完。
  绕过：`build --out-dir <系统临时目录>` + `serve --dir <同一目录>`（临时路径被守卫豁免）。
- 预览服务：`docusaurus serve` 会占端口。重新 build/serve 前先按端口取 PID 并 `taskkill`，
  否则旧进程会继续提供**过期产物**（踩过：看到的是上一版页面）。
- **移动端语义的验收必须开触摸模拟**：`Emulation.setDeviceMetricsOverride{mobile:true}` +
  `Emulation.setTouchEmulationEnabled{enabled:true}`，点按用 `Input.dispatchTouchEvent`（touchStart → 45ms → touchEnd，
  浏览器会补出 click）。此后 `matchMedia('(hover:hover)')=false`、`(pointer:fine)=false`、`(pointer:coarse)=true`，
  与真机一致。⚠️ **探针必须先 `scrollIntoView({block:'center'})` 把待点元素放进视口再派发坐标**，
  否则坐标落在视口外、等于什么都没点，会得到一堆假的"未居中"结论。
- **录 GIF 演示**：CDP `Page.startScreencast({format:'jpeg',quality:82,maxWidth,maxHeight,everyNthFrame:1})`
  + `Page.screencastFrame` 落盘 + `Page.screencastFrameAck`（不 ack 就不再推帧）。滚动时约 60fps。
  合成用本机 ImageMagick 7（`magick`，7.1.2）：按**真实时间戳**采样到目标帧率，逐帧 `-delay <ms/10>`，
  收尾 `-colors 128 -dither None -layers Optimize`（纯 UI 截图几乎无损，体积比 256 色 + FloydSteinberg 小 30%）。
  ⚠️ **逐帧延时不能设下限**：推帧间隔只有 ~16ms，下限抬到 45ms 会把总时长放大约 3 倍。
  🚨 **更根本的坑：screencast 是"变化驱动"的**——页面静止时几乎不产帧（"弹窗停留 1.8s"整段只录到 1 帧），
  滚动动画段却是 ~17–25ms/帧。所以**任何"按时间轴反推帧序号"的裁切都会错位**（曾据此裁出"弹窗没弹出来"的假象）。
  正解：`mark()` 时同时记 `frameIdx: frames.length` 当锚点，另存每帧真实墙钟 `times.json`；
  合成时按**分镜**组织——静止状态重复同一帧撑出停留，动画段按目标 fps 抽帧。
  另外别用"时间轴上的时刻"去描述静止段（源没有帧），要么重复帧、要么承认拍不到。
  无头截图看不到手指 → 点击提示改用**后期叠加**（`magick -draw "circle cx,cy cx+r,cy"`，半径递增 11→17→24，
  叠在每次点击前 3 帧），页面文件与 DOM 都不用动；⚠️ 涟漪坐标必须取**点击前那一帧**的视口坐标
  （滚动前先 `getBoundingClientRect()`），滚动后再取会画到别的地方去。
  ⚠️ 缓存涟漪图/中间帧要带 theme 前缀：亮暗两套素材的源帧序号会撞名（曾让暗色复用亮色的涟漪图）。
- 画审查图也用 `magick`（本机无 ffmpeg）：圈选坐标别目测，用
  `magick <图> -colorspace Gray -resize 1xN! -depth 8 txt:-` 取逐行灰度找**文字行带**再画多边形/矩形。
  中文要显式 `-font C:/Windows/Fonts/msyh.ttc`（默认字体无中文字形；`↩` U+21A9 在 msyh 里也缺字，改用文字描述）。
  多图拼版用 `+append`（`-tile/geometry` 那套 montage 语法在 `magick` 直连时无效，须 `magick montage`）。
- `magick` 会把同一规则里的声明**重新排序**（`display`/`position` 可能被挪到末尾），
  校验产物 CSS 时别用"声明紧跟选择器"的正则，否则会误判成"被 minifier 删掉了"。
